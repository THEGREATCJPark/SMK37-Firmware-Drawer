# UI 개선 기록

사용자 요청: Stageshow·unslop GitHub 레포를 참고해 기존 앱의 UI/UX를 개선하고 완성 결과를 보고한다. 기존 지시서에서 UI 판단을 위임했으므로 추가 승인 없이 실행한다. 실제 설치 프로토콜·보호 조건은 변경하지 않는다.

## 읽은 근거

- [Stageshow](https://github.com/benjitaylor/skills/tree/299140fafd08df55a9c234e610c3f64af3f45531/stageshow): SKILL.md, references/craft.md. Benji Taylor의 제품 일러스트레이션 도구. 실제 앱에는 문구 절제, 위계, 충분한 글자 크기, 간격과 의미 있는 동작의 원칙을 적용한다. 데모용 가상 UI나 filler를 실제 설치 화면에 넣지 않는다. kit 복사나 데모 제작을 한 것으로 주장하지 않는다.
- [unslop](https://github.com/heydamir/unslop/tree/97daa3eb365670ea3f87ed85356cbfcee18105a5): SKILL.md, references/signs.md, tokens.md, refs.md, visuals.md. Damir Sokolovsky (@heydamir), CC BY 4.0. 진단 → 방향 → 간격·색·아이콘·문구·타이포·레이아웃·세부·시각·동작 순서로 적용했다. 참조 가이드의 한국어 요약이며 원본 UI나 그림은 복제하지 않는다.

## 변경 전 진단

현재 production 화면을 1440px/390px에서 캡처했다. `output/playwright/redesign/before/`에 목록, 상세, 설치, 보관함, 포팅, 모바일 화면을 보관한다.

1. 목록: 큰 인사형 헤드라인과 기울어진 가상 카트리지가 실제 선택 작업보다 먼저 보인다.
2. 목록: 같은 제품명을 그림과 제목에 반복하고 모든 카드가 비슷한 비중이다. 각 설치 경로·버전 비교에는 긴 스크롤이 필요하다.
3. 전체: 세이지색 표면, 여러 중간색 텍스트, 7–11px 영문 라벨, 굵기 750–850와 좁은 자간이 가독성을 낮춘다.
4. 모바일: 상단 탐색과 홍보 영역이 높고 7개 용도 필터가 여러 줄을 차지한다. 카탈로그 첫 항목까지 접근이 늦다.
5. 설치: 이미지·제품 소개 아래에 첫 실제 작업이 놓인다. 비활성 검사 버튼이 왜 비활성인지 가까운 안내가 부족하다.
6. 보관·포팅: 불필요한 영문 캡션, 아이콘과 반복 설명이 실제 입력/파일 작업을 분산시킨다.
7. 탐색: 모델 선택이 목록에만 있어 보관·포팅 화면의 대상 확인이 불편하고 화면 전환 후 스크롤 위치가 남는다.

## 방향

- 제품: 내 SMK37의 펌웨어를 고르고, 정확한 파일을 확인하고, 개인 작업물을 보관하는 도구.
- 성격: 차분함, 정확함, 손에 익는 악기 관리.
- 소재: 중성 회색 장비 패널, 어두운 인쇄 글자, 작은 주황색 선택 표시.
- 강조점: 실제 제품 이름·버전·설치 경로, 설치 전 확인 상태.
- 고유 요소: 일정한 목록 번호와 정확한 모델명이 붙는 펌웨어 목록.

검토한 대안: 기존 큰 카트리지 유지 + 색상만 정리하면 탐색 밀도 문제는 남는다. 마케팅형 hero 또는 애니메이션 데모는 개인 도구의 작업 목적에 맞지 않는다. 따라서 현재 섹션과 기능을 유지하면서 제품 목록·작업 화면을 정리한다.

## 실행 계획

1. 4px 간격·12/14/16/20/32px 타입·중성 표면·최대 600 굵기·하나의 accent로 CSS를 다시 구성.
2. 목록을 제품/버전/설치 경로/상세 행동이 정렬된 행으로 바꿈. 전체 원문과 근거는 상세에 보존.
3. 모델 선택을 공통 헤더로 옮기고 모바일 탐색을 하단에 배치. 필터는 검색과 용도 선택, SMK 패키지 체크박스로 정리.
4. 상세와 설치의 맥락을 분리. 설치 시작 전에는 제품 장식보다 기기/파일/확인 단계가 먼저 보이게 함.
5. 백업/포팅의 문구·간격·형식을 같은 규칙으로 정리. 원본 계약·파일 검증·MIDI 정책은 유지.
6. 데스크톱·모바일, 키보드, 검색/필터, 빈 결과 초기화, 변경된 탐색을 검증하고 기존 안전 회귀시험을 실행.

### 시험한 UX와 회귀 범위

- 320·360·390·700·768·1024·1280px에서 목록·보관·포팅의 가로 넘침과 화면 전환을 확인했다.
- 오프라인에서도 320·360·700·768px 헤더의 모델 선택과 안내 버튼이 겹치지 않는다.
- 검색·용도 선택·빈 결과 초기화, 화면 간 모델 유지, 모델 변경 시 백업 확인값 초기화를 확인했다.
- 키보드 본문 이동, 상세 열기, Escape 닫기, 원래 버튼으로 초점 복귀를 확인했다.
- 설치 준비에서 첫 작업·검사 불가 이유·실기 미검증 표시가 보이고, 최종 설치 버튼이 조기에 나타나지 않음을 확인했다.
- 기존 실제 패키지 검사, 모의 MIDI 프로토콜, 탭 잠금, 중단·재개, 외부 이동 이력, 오프라인 파일 재검증 시험을 다시 통과했다.

독립 코드 검토에서 공통 모델 선택 도입에 따른 백업 확인값 재사용과 설치 화면의 실기 미검증 문구 노출 문제를 찾아 수정했다. 추가 UX 시험에서 확인한 모달 초점 복귀도 수정했다. 최종 재검토에 남은 critical/important 지적은 없다.

`src/install/`, `src/catalog/`, `src/storage/`, `src/porting/`, `src/vendor/`, `scripts/firmware/`의 핵심 설치·파일 계약에는 이번 UI 변경이 없다. 실제 USB 권한 요청, 업데이트 모드 진입, 펌웨어 기록·지우기·복구는 실행하지 않았다. 실제 Galaxy 검증이나 전체 접근성 인증을 의미하지 않는다. 빌드의 기존 Lucide 지시문 경고 2개는 [검증 기록](verification.md)에 설명했다.
