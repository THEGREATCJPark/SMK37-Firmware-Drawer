# 웹 내 패키지 다운로드와 설치

외부 설치기 이동을 기본 경로로 삼았던 초기 구현을 수정했다. 다음 다섯 제품은 선택한 모델의 파일을 이 웹에서 받고 검증한 뒤 같은 화면에서 MIDI 설치를 시작한다. 사용자 최종 클릭 전에는 기록하지 않는다.

| 제품 | 버전 | Pro / Elite / MKE 파일 수 |
| --- | --- | --- |
| SLOOP Pro | 2.8.4 | 3 |
| Frodhes | 0.9.2, 0.9.9 | 6 |
| Erik37 | 1.2 | 3 |
| OberVave | 3.3.2 | 3 |
| ChoralRoot | 0.29 SMK, 기본·1core | 6 |

총 21개 파일의 실제 SHA-256·크기·identity·CRC·보드 영역을 검증했다. 상세 화면에서 버전을 고를 수 있다. 설치 준비의 **이 웹에서 패키지 받기**는 페이지 이동 없이 다운로드하며 검증을 통과한 바이트만 다음 단계에 사용한다. 오프라인 보관은 별도 사용자 행동이며 서비스 워커가 모든 펌웨어를 미리 받지 않는다. 네트워크 실패·시간 초과·파일 변조 시 설치 버튼을 열지 않는다.

SLOOP Pro·Frodhes 0.9.2·Erik37·ChoralRoot는 검증된 원저자/기존 공개 배포 주소에서 CORS로 읽는다. Frodhes 0.9.9와 OberVave는 릴리스 원본을 빌드 중 내려받아 고정 SHA를 검사하고 Pages에 포함한다. 파일은 변경하지 않는다. `packages/NOTICE.json`에 저자·라이선스·원본 파일·대응 소스 아카이브 링크를 제공한다. 출처와 매뉴얼 링크는 참고 자료로 남긴다.

## 로더 식별자 교정

앱 identity와 loader identity를 분리했다. 21개 실제 패키지의 type-100 loader에 들어 있는 문자열은 모두 `ota-<모델>_900`이다. 앱은 Frodhes `_470`, Erik37 `_480102`, OberVave `_9533`, ChoralRoot `_920` 등으로 답하므로 앱 이름에 `ota-`를 붙이는 기존 가정은 틀렸다. 카탈로그의 `loaderIdentity`를 파일 내부 문자열과 대조하고, 재연결 시 그 값을 검사한다. 모의 기기도 패키지에서 실제 loader 이름을 읽는다.

여러 제품이 같은 loader 이름을 공유하므로 loader 응답만으로 재개하지 않는다. 이 앱의 최근 중단 이력·정확한 artifact·SHA·실물 모델이 모두 일치해야 한다. 다른 파일이나 외부 설치 이력이 끼어 있으면 재개를 거절한다.

## 아직 통합되지 않은 대상

- **+VA 102**: 원저자 파일은 개인 검토용으로 받아 SHA와 패키지 구조를 확인했다. 서버는 타 origin의 fetch를 허용하지 않으며 설치 페이지는 `X-Frame-Options: DENY`, `frame-ancestors 'none'`으로 삽입도 금지한다. 공개 재배포 허가가 확인되지 않아 이 공개 저장소/Pages에 복제하지 않았다. 사용자에게 원저자의 허가 여부를 질문한 상태다. 이 파일은 Felucca loader가 아닌 다른 로더와 영역 구조를 사용하므로 기존 adapter의 검사만 해제해 통과시키지 않는다. +VA는 현재 외부 경로다.
- **sloopDX**: 확인한 원본은 FM-1용이다. SMK37용 패키지가 생긴 것처럼 표시하지 않으며 별도 포팅 작업으로 유지한다.

실제 USB 업데이트·기록·복구는 수행하지 않았다. 모의 프로토콜과 파일 검사 통과는 실기 설치 성공을 의미하지 않는다.

## 검증 결과

최종 `npm run check` exit 0. 단위 시험 50개(122.19초), TypeScript·Vite·PWA 빌드, Chrome/Edge 브라우저 시험 30개(20.7초)를 통과했다. 21개 실제 주소를 브라우저에서 읽어 HTTP 200·크기·SHA 일치를 확인했다. 실제 파일을 이용한 여섯 버전의 전체 logical image 모의 전송, 실제 loader 이름으로 동작하는 선택 포트 어댑터, 변조·과대 응답·취소를 검사했다. 독립 재검토에 남은 critical/important 지적은 없다.
