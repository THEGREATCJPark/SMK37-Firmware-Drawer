# 같은 웹에서 일곱 제품 설치

카탈로그의 SMK-37 Pro / SMK-37 Elite / MKE-P37 항목은 모두 이 웹의 **상세 → 파일 검사·설치 준비 → 이 웹에서 패키지 받기**로 연결된다. 최종 설치 버튼을 누르기 전에는 기록하지 않는다.

| 제품 | 제공 버전 | 모델별 항목 |
| --- | --- | --- |
| SLOOP Pro | 2.8.4 | 3 |
| Frodhes | 0.9.2, 0.9.9, 0.9.10 | 9 |
| Erik37 | 1.2 | 3 |
| OberVave | 3.3.2 | 3 |
| ChoralRoot | 0.29 기본·1core | 6 |
| +VA | 102, 공통 파일 | 3 |
| sloopDX | 4.0.1-smk37-preview.1, 실험 포트 | 3 |

30개 모델별 설치 항목(서로 다른 파일 28개). FM-1 원본 파일은 SMK37 설치 대상이 아니다. 상세 화면에서 제공 버전을 고를 수 있다. 해시·크기·CRC·실제 identity·보드 영역을 검증한 바이트만 사용한다. 오프라인 보관은 명시적 행동이며 서비스 워커가 펌웨어를 미리 받지 않는다.

## +VA 사용

1. [Windows 개인 다운로드 도우미](https://github.com/THEGREATCJPark/SMK37-Firmware-Drawer/releases/download/download-helper-v1/SMK37-Download-Helper-Windows.zip)를 풀고 `Start-Helper.cmd`를 실행한다. Node 런타임이 포함되어 별도 설치는 필요 없다.
2. Chrome/Edge에서 웹 앱의 +VA 설치 화면을 연다. 다운로드 버튼을 누르고 브라우저가 요청하면 로컬 네트워크 연결을 허용한다.
3. 도우미는 `127.0.0.1:19437`에서 고정된 원저자 펌웨어와 기본 음색 두 파일만 받아 크기/SHA-256을 확인한다. MIDI/USB·개인 파일·임의 URL에 접근하지 않는다. 작업 후 창을 닫는다.
4. 현재 기기는 모델에 맞는 **순정 V016**이어야 한다. 다른 커스텀 펌웨어에서 +VA로 직접 전환하는 경로는 검증되지 않았다. 해당 모델의 순정 복귀 절차를 먼저 사용한다. 현재 SLOOP Pro의 보드 검사는 flash 이미지 0x9D000을 요구하지만 +VA는 0xBA000이므로, staging 전에 거절된다. 이 앱이 순정 복구를 자동 실행하지는 않는다. +VA102에서 Felucca 계열로 나가는 경로는 별도로 지원한다.
5. 전체 백업 검증과 복구 준비를 등록한다. 별도 초기화 동의 후에만 설치한다. +VA 펌웨어 뒤 기본 음색 128개와 빈 패턴 16개를 준비하고 읽어 검증한다. 기존 음색·패턴은 교체되며 7분 이상 걸릴 수 있다. 전역 설정 전체를 공장 초기화한다는 의미는 아니다.
6. 데이터 준비 중 끊겨 이미 +VA102가 실행되는 경우, 같은 기기·파일의 최근 중단 기록으로 재개하면 펌웨어를 다시 기록하지 않고 데이터 준비만 이어간다. 자동 재개는 없다.

원저자 서버는 브라우저 교차 출처 다운로드/설치기 삽입을 허용하지 않는다. 따라서 공개 재배포 허가가 확인되지 않은 +VA 펌웨어·음색을 저장소나 Pages에 복제하지 않고 개인 도우미가 원저자에게 요청한다. 도우미에는 앱 코드와 Node 런타임만 포함한다. Windows 도우미 방식이므로 Android만으로 +VA 전체 절차를 수행하는 기능은 제공하지 않는다.

## sloopDX 실험 포트

이 프로젝트가 고정 upstream 소스에 SMK 보드 계층·모델별 loader·저장 배치를 적용해 만든 preview.1이다. 세 모델 빌드, 모의 보호 영역·저장/복구, FM-1 기준 바이너리 동일성을 검사했다. 실제 부팅·음색·입력·LCD/LED·저장·순정 복귀는 미검증이다. 카탈로그와 설치 화면에 실험 표시를 유지하고 별도 최종 확인을 요구한다. 상세 근거와 재현 방법은 [포트 보고서](sloopdx-port.md).

릴리스에는 세 바이너리, 고정 manifest, 패치 및 대응 소스 아카이브를 함께 제공한다. 제한된 아이콘 그림은 SMK 빌드에서 제외하고 텍스트를 표시한다. 가져온 임의 빌드 번들은 자동 설치 대상으로 승격하지 않는다.

## 다운로드와 재개 검사

기존 CORS 지원 배포 주소는 직접 읽고, Frodhes 0.9.9/0.9.10·OberVave 및 sloopDX는 릴리스 고정 해시를 빌드 중 확인해 Pages에 제공한다. `packages/NOTICE.json`에서 원저자·소스·라이선스·대응 소스 아카이브를 확인한다.

Felucca 앱 identity와 loader identity는 별도로 검증한다. 실제 loader는 `ota-<모델>_900`이고 앱은 제품에 따라 `_470`, `_480102`, `_9533`, `_920`, `_900`이다. +VA는 전용 고정 이미지 검사와 출발 순정 펌웨어의 loader를 사용한다. +VA 전용 체크섬 호환 처리는 다른 패키지 경로에 적용하지 않는다.

같은 loader 이름만으로 재개하지 않는다. 최근 중단 이력·artifact·SHA·실물 모델·출발 identity가 일치해야 한다. 포트는 사용자가 선택한 쌍만 사용하며, 매 재열거 때 identity를 다시 검사한다. 네트워크·파일·응답 검증 실패 시 완료로 기록하지 않는다.

## 검증 범위

실제 USB/플래시 기록은 수행하지 않았다. 소프트웨어 및 모의 프로토콜 검증 결과는 실기 설치 성공을 의미하지 않는다. sloopDX 원본 host suite의 ThreadSanitizer는 WSL 주소 배치 오류로 시작하지 못했으며 통과로 처리하지 않았다. 나머지 세 모델 집중 시험과 61개 원본 오디오 골든 결과는 보고서에 기록했다.
