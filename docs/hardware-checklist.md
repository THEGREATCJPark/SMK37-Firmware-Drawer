# 사용자가 수행할 최소 실기 시험

이 작업에서는 기기 쓰기, 업데이트 모드 진입, erase/restore를 실행하지 않았다. 정상 설치가 확인되기 전에는 의도적인 전원 차단 시험을 하지 않는다.

1. **현재 상태**: 실물 모델, 현재 화면의 제품/버전, OS·브라우저·케이블을 기록한다. 다른 MIDI 앱과 다른 설치기 탭을 닫고 다른 MIDI 장치를 분리한다.
2. **전체 백업**: [포팅 키트의 고정 백업 절차](https://github.com/genkigenki/fm1-to-smk37/blob/54252ffa2219e3c9cd7eb70f4e99b361eaa048e1/docs/02-update-and-recovery.md#3-full-flash-backup-do-this-first)에서 해당 모델의 도구를 확인한다. 서로 독립적으로 읽은 1 MiB 덤프 두 개의 SHA-256과 `0xC1224`의 `trimdat`를 확인하고 두 곳에 보관한다. 앱에는 검증 기록을 등록한다. 전체 덤프·보정값은 공개하지 않는다.
3. **작업물과 복귀**: 현재 펌웨어 에디터에서 음색·곡·샘플·설정을 별도 저장한다. 현재 버전의 정확한 패키지와 모델별 공식 복구 도구를 준비한다. 설치 패키지만으로 작업물이 복원되지는 않는다.
4. **목표 A**: Pro라면 고정 SLOOP Pro 2.8.4 또는 Frodhes SMK 0.9.2를 선택한다. 파일 검사를 마치고 데이터 영향을 읽은 뒤 **사용자가 앱에서 설치 시작**을 누른다. 전원·USB·탭을 유지하고 재열거 때 같은 기기의 입력/출력을 다시 선택한다.
5. **확인**: 재연결 identity를 기록하고 키·벨로시티·패드·노브·페이더·휠·페달·오디오·화면·저장·정상 재부팅을 확인한다. 성공 identity만으로 이 항목들을 통과 처리하지 않는다.
6. **목표 B와 복귀**: A의 정상 동작과 백업을 확인한 뒤 지원표의 경로로 B를 설치하고 같은 점검을 반복한다. 원 버전 패키지 재설치와 호환 family/version/schema의 작업물 복원을 각각 확인한다.

연결이 끊기거나 화면이 잠겼다면 케이블을 임의로 재삽입/강제 재부팅하기 전에 로그와 실제 상태를 확인한다. 앱은 자동 재시도하지 않는다. 같은 loader·파일·최근 중단 이력이 모두 맞을 때만 일반 재개가 열린다. 이력이 없거나 외부 도구를 썼다면 원래 설치기의 복구 안내로 돌아간다. 백업이나 복구 경로가 불명확하면 기록을 시작하지 않는다.

시험 기록: 날짜 / 실물 모델 / 출발 제품·버전 / 목표 파일·SHA / OS·브라우저 / 케이블 / 전송·재연결 / 패널·오디오·저장 결과 / 원복 결과. 실기 결과는 별도 검토 후 지원표에 추가한다.
