# SMK37 Firmware Drawer

SMK37 개인용 펌웨어 카탈로그, 고정 패키지 설치 준비, 백업 파일 보관과 FM-1 포팅 작업실. 개인 파일은 계정·원격 업로드 없이 브라우저에 저장합니다. 실제 기기 기록은 사용자가 앱의 최종 버튼을 눌렀을 때만 시작됩니다.

## 실행

Windows에서 `Start-Drawer.cmd`를 더블클릭한 뒤 **http://127.0.0.1:4173/** 을 Chrome 또는 Edge에서 여세요. 실행 창을 닫으면 로컬 서버가 종료됩니다. 이미 실행 중이면 주소만 여세요.

명령줄에서는 이 폴더에서 다음을 실행합니다. 검증 환경은 Node 22.18.0 / npm 10.9.3입니다.

```powershell
npm ci
npm run build
npm run preview
```

개발 중에는 `npm run dev`. preview와 같은 포트를 사용하므로 동시에 실행하지 않습니다. `localhost`와 `127.0.0.1`은 저장소가 다르므로 위 주소를 일관되게 사용하세요. GitHub Pages 웹 앱도 제공합니다.

## 사용할 수 있는 기능

- 7개 제품, 36개 모델별 아티팩트의 출처·버전·제약·백업/복구 정보, 검색과 즐겨찾기.
- 모델별 고정 패키지 다운로드, hash/CRC/모델/영역 검사, 명시적 오프라인 보관.
- +VA 전용 어댑터: 원저자 파일을 도우미로 받아 설치하고, 별도 초기화 동의 후 128개 기본 음색과 16개 빈 패턴을 기록·읽기 검증합니다.
- 전체 플래시의 **사용자 검증 기록**, 펌웨어별 프로젝트 파일, 설치 패키지를 구별하는 보관함. 내보내기/가져오기 지원.
- 기존 SLOOP Pro 소스 재현 빌드 recipe와 실제 빌드 번들 가져오기. sloopDX는 고정 소스의 세 모델 실험 빌드를 제공합니다. 임의로 가져온 결과는 여전히 `build-only`이며 자동 설치 대상이 되지 않습니다.
- 동일 origin의 탭 간 MIDI 잠금, 선택한 포트만 탐색, 중단 이력/동일 SHA로 제한한 재개. 사용자 최종 클릭 전에는 식별 요청만 가능합니다.

**소프트웨어 검증과 실기 지원은 다릅니다.** USB 쓰기, 음색·패널·저장, 실제 Android USB는 미검증입니다. 모든 설치 대상의 실제 파일을 자동 검사했고 전송·저장은 모의 기기로 시험했습니다. [지원표](docs/support-matrix.md)를 확인하세요.

## 첫 사용

1. 실물 모델과 현재 펌웨어를 확인합니다. [실기 체크리스트](docs/hardware-checklist.md)에 따라 전체 백업과 복귀 경로를 준비합니다.
2. ‘백업과 이력’에서 사용자 검증 기록을 등록하고, 기존 에디터의 음색·곡·샘플 파일도 따로 보관합니다.
3. 목록의 ‘상세 보기’ → ‘파일 검사·설치 준비’에서 연결, 포트 선택, 정확한 파일 검사까지 진행합니다.
4. 데이터 영향을 확인한 뒤 사용자가 ‘이 기기에 설치 시작’을 누릅니다. 업데이트 모드와 설치 후 포트는 다시 선택합니다. 같은 물리 기기를 유지하세요.

브라우저 저장소는 삭제될 수 있습니다. 중요한 파일은 원본 저장장치에도 보관하세요. 공개 패키지와 원본 프로젝트 복원은 별개입니다. 새로고침/중단 후 자동 재시도는 없습니다. 이 앱의 최근 중단 이력이 없거나 외부 설치기를 연 뒤에는 일반 재개를 허용하지 않습니다.

## 검증 재실행

```powershell
npm run fixtures
npm test
npm run build
npm run test:ui
```

fixtures는 카탈로그의 고정 파일을 `.local/packages`에 내려받아 SHA-256을 검사합니다. GPL 배포 패키지는 일부 Pages에 포함하고 대응 소스를 연결합니다. +VA 펌웨어/음색은 공개 저장소·Pages·도우미 ZIP에 포함하지 않습니다. UI 검증은 설치된 Windows Chrome/Edge를 사용하며, 실제 MIDI 대신 명시적 모의 포트를 씁니다. 전체 UI 시험에는 실제 재현 빌드 번들이 필요하므로 새 checkout에서는 [포팅 절차](docs/porting-workflow.md)를 먼저 실행하세요. 이 작업 공간에는 번들이 이미 생성되어 있습니다.

시험 결과와 한계: [검증 기록](docs/verification.md), [펌웨어 빌드 보고서](docs/build-report.md), [Stageshow·unslop 기반 UI 개선 기록](docs/ui-redesign.md). 원본 host suite 일부는 실패했고 통과로 처리하지 않았습니다.

최종 시험 수와 결과는 [통합 검증 기록](docs/integrated-installation.md)을 확인하세요. 이전 화면이 남아 있으면 앱 탭을 모두 닫은 뒤 다시 여세요. 설치 도중 새 버전으로 강제 전환하지 않습니다.

## 2026-11-12 · Hub에서 발전시킨 기능

- **새 배포 확인**: 매일 GitHub Actions가 고정 제작자 저장소의 최근 정식 릴리스를 조사한다. FM-1 원본과 SMK 설치 버전을 혼동하지 않도록 나란히 표시하며 새 파일을 자동 승인하지 않는다.
- **실제 출처 증명 검사**: 고정 파일을 다운로드해 크기/SHA를 확인한 후 GitHub CLI가 attestation을 검증한다. 기대 저장소·파일 digest·인증서 소스 커밋·statement 소스 의존성을 대조한다. 파일 무결성, 빌드 출처, 실기 시험을 별도 항목으로 표시한다.
- **차단 유지**: 명시적 증명 실패와 소스 불일치는 준비/시작/최종 기록 직전에서 차단한다. 일시적인 서버 오류로 이전 차단 근거를 지우지 않는다. 증명 없음과 서버 조회 실패는 검증 실패와 구별한다.
- **실제 로컬 덤프 비교**: 독립적으로 읽은 두 1MiB 덤프를 선택하면 크기·바이트·SHA·trimdat를 검사한다. 원본은 업로드되지 않는다. 소유자/모델/별도 보관은 사용자 확인이 필요하다. 수동 기록과 앱의 두 파일 검사 기록을 구별한다.
- **복구 도우미**: 연결 실패·로더 중단·부팅 실패·순정 복귀를 구분하고 선택 모델의 출처와 로컬 보고서를 제공한다. 보고서에 덤프 bytes·경로·개인 메모·브라우저 문자열을 넣지 않는다. 자동 복구 명령은 없다.
- **Frodhes 0.9.10**: 세 모델의 공식 고정 파일을 추가했다. 0.9.2/0.9.9도 유지한다. 버전 선택에서 직접 고른다. MKE 순정 설정 첫 섹터 영향과 실기 미검증을 명시한다.
