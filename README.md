# SMK37 Firmware Drawer

SMK37 개인용 펌웨어 카탈로그, 고정 패키지 설치 준비, 백업 파일 보관과 FM-1 포팅 작업실. 서버·계정·원격 업로드 없이 브라우저에 저장합니다. 실제 기기 기록은 사용자가 앱의 최종 버튼을 눌렀을 때만 시작됩니다.

## 실행

Windows에서 `Start-Drawer.cmd`를 더블클릭한 뒤 **http://127.0.0.1:4173/** 을 Chrome 또는 Edge에서 여세요. 실행 창을 닫으면 로컬 서버가 종료됩니다. 이미 실행 중이면 주소만 여세요.

명령줄에서는 이 폴더에서 다음을 실행합니다. 검증 환경은 Node 22.18.0 / npm 10.9.3입니다.

```powershell
npm ci
npm run build
npm run preview
```

개발 중에는 `npm run dev`. preview와 같은 포트를 사용하므로 동시에 실행하지 않습니다. `localhost`와 `127.0.0.1`은 저장소가 다르므로 위 주소를 일관되게 사용하세요. 외부 배포는 하지 않았습니다.

## 사용할 수 있는 기능

- 7개 제품, 33개 모델별 아티팩트의 출처·버전·제약·백업/복구 정보, 검색과 즐겨찾기.
- SLOOP Pro 2.8.4 / Frodhes SMK 포트 0.9.2의 고정 패키지 설치 어댑터. 로컬 `.fwsc` 파일을 선택해 hash/CRC/모델/영역을 검사하고 명시적으로 오프라인 보관합니다.
- +VA, Erik37, OberVave, ChoralRoot 등의 개발자 설치기 연결. 외부 열기는 완료로 기록하지 않습니다.
- 전체 플래시의 **사용자 검증 기록**, 펌웨어별 프로젝트 파일, 설치 패키지를 구별하는 보관함. 내보내기/가져오기 지원.
- 기존 SLOOP Pro 소스 재현 빌드 recipe와 실제 빌드 번들 가져오기. sloopDX 신규 포팅은 작업 명세 내보내기까지 연결하며, 가져온 결과는 항상 `build-only`입니다.
- 동일 origin의 탭 간 MIDI 잠금, 선택한 포트만 탐색, 중단 이력/동일 SHA로 제한한 재개. 사용자 최종 클릭 전에는 식별 요청만 가능합니다.

**소프트웨어 검증과 실기 지원은 다릅니다.** USB 쓰기, 음색·패널·저장, 실제 Android USB는 미검증입니다. Pro 실제 패키지 두 종을 자동시험에 사용했고 Elite/MKE는 공개 아티팩트와 모델 분기 소스 근거입니다. [지원표](docs/support-matrix.md)를 확인하세요.

## 첫 사용

1. 실물 모델과 현재 펌웨어를 확인합니다. [실기 체크리스트](docs/hardware-checklist.md)에 따라 전체 백업과 복귀 경로를 준비합니다.
2. ‘백업과 이력’에서 사용자 검증 기록을 등록하고, 기존 에디터의 음색·곡·샘플 파일도 따로 보관합니다.
3. 목록의 ‘상세 보기’ → ‘파일 검사·설치 준비’에서 연결, 포트 선택, 정확한 파일 검사까지 진행합니다.
4. 데이터 영향을 확인한 뒤 사용자가 ‘이 기기에 설치 시작’을 누릅니다. 업데이트 모드와 설치 후 포트는 다시 선택합니다. 같은 물리 기기를 유지하세요.

브라우저 저장소는 삭제될 수 있습니다. 중요한 파일은 원본 저장장치에도 보관하세요. 공개 패키지와 원본 프로젝트 복원은 별개입니다. 새로고침/중단 후 자동 재시도는 없습니다. 이 앱의 최근 중단 이력이 없거나 외부 설치기를 연 뒤에는 일반 재개를 허용하지 않습니다.

## 검증 재실행

```powershell
npm run fixtures
npm test
npm run build
npm run test:ui
```

fixtures는 고정 공개 파일 세 개를 `.local/packages`에 내려받아 SHA-256을 검사합니다. 배포물에는 바이너리를 넣지 않았습니다. UI 검증은 설치된 Windows Chrome/Edge를 사용하며, 실제 MIDI 대신 명시적 모의 포트를 씁니다. 전체 UI 시험에는 실제 재현 빌드 번들이 필요하므로 새 checkout에서는 [포팅 절차](docs/porting-workflow.md)를 먼저 실행하세요. 이 작업 공간에는 번들이 이미 생성되어 있습니다.

시험 결과와 한계: [검증 기록](docs/verification.md), [펌웨어 빌드 보고서](docs/build-report.md), [Stageshow·unslop 기반 UI 개선 기록](docs/ui-redesign.md). 원본 host suite 일부는 실패했고 통과로 처리하지 않았습니다.

UI 개선 후 단위 시험 42개·Chrome/Edge 브라우저 시험 26개와 production 빌드를 통과했습니다. 이전 화면이 남아 있으면 앱 탭을 모두 닫은 뒤 다시 여세요. 설치 도중 새 버전으로 강제 전환하지 않습니다.

## 파일 안내

| 경로 | 역할 |
| --- | --- |
| `src/catalog/` | 출처 포함 카탈로그와 런타임 schema |
| `src/install/`, `src/vendor/` | 설치 정책·상태·선택 포트 어댑터와 고정 upstream 프로토콜 |
| `src/storage/`, `src/porting/` | 개인 파일/이력, 작업·번들 계약 |
| `scripts/firmware/` | 고정 WSL 빌드 recipe, USB 작업 없음 |
| `tests/` | 실제 파일 parser, wire mock, 상태·보관·브라우저 검증 |
| `docs/` | 조사, 구현 판단, 지원표, 실기 체크리스트 |
